# RescueNet-X Audit Remediation Report & Changelog (`CHANGES.md`)

This document records the complete, phased architectural audit and remediation of **RescueNet-X** (FastAPI backend + React 19 / Vite frontend). All fixes adhere strictly to the project ground rules, preserving the canonical Section 4.5 event payload schema contract, ensuring 100% offline functionality without API keys, maintaining real measured performance benchmarks, and proceeding via isolated, phased git commits without force-pushing.

---

## 1. Ground Rules & Schema Contract Compliance

* **Section 4.5 Canonical Payload Invariant**: The 10 canonical fields (`category`, `coordinates`, `sector`, `severity`, `casualty_count`, `summary`, `confidence`, `source`, `raw_transcript`, `verified`) are strictly preserved across all routes, agents, and WebSocket messages. Pydantic validation now enforces strict enums, ranges, and types, returning HTTP 422 on invalid requests rather than falling back silently or raising HTTP 500.
* **100% Offline Capability**: All core workflows (the 3 crisis scenarios: flood, medical, fire; phone audio simulator; visual image triage; and one-click CAD tactical dispatch) function completely offline without cloud API keys. Offline heuristic extractors, local Whisper STT, YOLOv11 person counting, and local OpenCV image analytics operate reliably on local hardware.
* **Empirical Integrity**: No metrics or latencies are fabricated. All performance numbers displayed in the UI, Pitch Deck, and README are backed by measured benchmarks generated by `scripts/benchmark.py` and stored in `benchmarks.json`.
* **Clean Commits**: History is cleanly maintained across individual phase commits. No force-pushes or history rewrites were performed.

### Phase 1 — Correctness & Logic Bugs (Commit `7ee7d89`)
* **Unit State Lifecycle & Tactical Routing**:
  * When `routing_agent` assigns a rescue unit, it immediately marks its state as `EN_ROUTE`.
  * `find_nearest_unit` now strictly filters for units with status `AVAILABLE`.
  * Implemented `POST /api/events/{id}/resolve` which marks an incident `RESOLVED`, frees the assigned unit back to `AVAILABLE`, and broadcasts `UNIT_UPDATE` and `INCIDENT_UPDATE` over WebSocket.
  * When no suitable unit is available, incidents are safely queued as `PENDING` with a clear audit log entry.
* **Voice & IVR Coordinate Normalization**:
  * Removed hardcoded voice coordinates.
  * When coordinates are not provided, IVR inputs are routed through a configurable sector and landmark lookup table. If unresolved, incidents are created with `location_unknown=true` and placed with slight coordinate jitter near the default center so callers do not merge inadvertently into duplicate incidents.
* **Urgency Scoring vs. Raw Severity**:
  * Preserved the original triage model severity in `raw_severity`.
  * Separated `urgency` into a configurable weighted calculation (`URGENCY_WEIGHT_SEVERITY * raw_severity + URGENCY_WEIGHT_CASUALTIES * casualties + URGENCY_WEIGHT_CONFIDENCE * confidence`).
  * Removed the unjustified +1 voice channel bonus. Priority 1 is now awarded only when calculated urgency strictly exceeds 8.0.
* **Robust Deduplication**:
  * Visual perceptual hash dedup now strictly requires category matching before merging.
  * Spatial deduplication now enforces both distance ($\le 500\text{ m}$) and a temporal window ($\le 30\text{ minutes}$).
  * Merged duplicate reports re-broadcast updated `cluster_count` and timestamps over WebSocket.
* **Vision & Triage Heuristics**:
  * Completely removed the filename-based category shortcut in `vision_engine.py`.
  * Capped color/edge heuristic confidence at $\le 0.80$, preventing automated unverified dispatch without operator review.
  * Grounded verified status ($\ge 0.85$) in multi-modal LLM classifier verification (Gemini Vision API) when configured.
  * Fixed rubble and structural collapse misclassification from `FLOOD` to `RESCUE`.
  * Clarified YOLOv11 usage strictly for person counting, not disaster categorization.
* **Speech-to-Text & Gemini Fallbacks**:
  * Replaced fabricated transcripts on silent or corrupted audio with status `MANUAL_REVIEW`, confidence 0.3, `verified=False`, and summary `"Unintelligible audio, operator review required"`.
  * Removed dummy WAV file writes.
  * Derived voice confidence and verification dynamically from extraction signals rather than hardcoding `verified=True, confidence=0.90`.
  * Updated default Gemini model to supported `gemini-1.5-flash` with fail-soft error handling.
  * Switched Gemini authentication from URL query parameter to the `x-goog-api-key` header.
* **Strict Validation & Modern Lifespan**:
  * Enforced strict Pydantic models with `ge`/`le` validation for coordinates, severities, casualty counts, and valid categorical enums.
  * Replaced deprecated `@app.on_event("startup")` with FastAPI `lifespan` context manager.
  * Added global exception handler and Pydantic validation error handler returning structured HTTP 422 responses.

### Phase 2 — Security & Attack Surface Hardening (Commit `2d13a7d`)
* **Administrative Authentication**:
  * Added `ADMIN_TOKEN` authentication requirement for privileged routes (`/api/simulate/reset`, `/api/config/*`, `/api/dispatch/*`, `/api/events/*/resolve`, and `/api/config/test-gemini`).
  * Accepts either `X-Admin-Token` header or `Authorization: Bearer <token>`.
  * Automatically generates and displays a secure 256-bit random token on startup if unset in environment.
  * Added operator token prompt in frontend UI storing key strictly in `sessionStorage`.
* **CORS Restrictions**:
  * Eliminated wildcard `*` with credentials. Replaced with strict whitelist of allowed origins (`localhost:5173`, `localhost:8000`, `127.0.0.1:5173`, `127.0.0.1:8000`, and custom origins configured via `ALLOWED_ORIGINS`).
* **Atomic Environment File Updates**:
  * Implemented `secure_save_env_keys` with strict key whitelisting (`ALLOWED_ENV_KEYS`).
  * Rejects values containing CRLF (`\r`, `\n`) or null bytes (`\0`) to prevent `.env` file pollution and header injection.
  * Writes atomically using temporary files and atomic replacements (`os.replace`) guarded by a mutex lock. Prohibited setting arbitrary network endpoints like `OLLAMA_ENDPOINT` via API.
* **SSRF Mitigation**:
  * Validates Twilio `RecordingUrl` in `/api/voice/process-audio`, enforcing HTTPS and exact host match (`api.twilio.com`) with size and connection timeouts. Rejects loopback (`127.0.0.1`, `localhost`) and metadata IP ranges (`169.254.169.254`).
* **Twilio Webhook Verification**:
  * Implemented `twilio.request_validator.RequestValidator` checking `X-Twilio-Signature` on all `/api/voice/*` webhooks when production Twilio credentials are configured.
* **File Upload Hardening**:
  * Implemented magic byte and MIME sniffing using Pillow (`Image.open().verify()`) and standard audio header inspection. Disguised executables (.exe renamed to .jpg) are rejected immediately.
  * Generated secure random server-side filenames, ignoring client-supplied paths to prevent directory traversal.
  * Enforced strict size ceilings (8 MB image, 10 MB audio).
  * Injected security headers (`X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, strict `Content-Security-Policy`, and explicit script execution block on `/uploads/`).
* **Rate Limiting**:
  * Integrated an in-memory IP sliding-window rate limiter on public POST routes (`/api/report/pwa`, `/api/report/visual`, `/api/voice/process-audio`).

### Phase 3 — Reliability & Architecture (Commit `6d45785`)
* **Asynchronous Offloading**:
  * Wrapped blocking synchronous AI and image processing routines (Whisper STT, YOLO inference, OpenCV edge/color analysis, and external HTTP calls) with `starlette.concurrency.run_in_threadpool`, ensuring the async event loop and WebSocket broadcasts remain non-blocking and responsive.
* **SQLite Persistence**:
  * Replaced volatile in-memory dictionary storage with a persistent SQLite database (`cad_store.db`).
  * Persisted `events`, `units`, and `dispatch_log` tables across server reboots.
  * Maintained full backwards compatibility with the existing `IncidentStore` interface.
  * Guarded database transactions with `threading.Lock` and connection pooling for concurrent thread safety.
* **High-Reliability WebSocket Subsystem**:
  * Guarded connection pool modifications with `asyncio.Lock`.
  * Upgraded broadcasts to concurrent non-blocking `asyncio.gather` with a 1.0-second per-connection timeout to protect against slowloris clients.
  * Introduced monotonic message sequencing (`seq`) enabling clients to detect message drops and request gap resynchronization (`RESYNC`).
  * Added server-side timestamped ping/pong protocol for true round-trip latency measurement.
  * Integrated `INITIAL_STATE`, `UNIT_UPDATE`, and `DISPATCH_CONFIRMED` events into the resynchronization flow.
* **Structured Logging & Pagination**:
  * Replaced unformatted `print()` statements with Python's standard `logging` module.
  * Added `X-Request-ID` tracing middleware for all incoming HTTP requests.
  * Added pagination (`limit`, `offset`) to `GET /api/events` with stored incident caps to guard against memory exhaustion.
  * Enhanced `GET /health` with database status, AI model availability, active WebSocket connection counts, and total stored incidents.

### Phase 4 — Frontend Architecture, UX & Accessibility (Commit `576d81a`)
* **CitizenPortal Offline Resilience & GPS Gating**:
  * Automatically requests geolocation on component mount. Displays clear GPS telemetry indicators (`ready`, `acquiring`, `denied`, `unsupported`).
  * Hard-gates the Emergency SOS button until valid coordinates are captured, preventing zero-coordinate dispatch failures.
  * Implemented an offline outbox backed by `localStorage` (`rescuenet_offline_outbox`). Failed citizen reports queue automatically and flush upon network reconnection or manual trigger.
* **PWA & Offline Asset Caching**:
  * Created `frontend/public/sw.js` implementing stale-while-revalidate and network-first strategies for app shell, scripts, and local fonts.
* **WebSocket Backoff & Latency Telemetry**:
  * Replaced flat reconnection loops with exponential backoff ($1\text{s} \to 2\text{s} \to 4\text{s} \dots \max 15\text{s}$) featuring a live alert countdown banner (`role="alert"`).
  * Removed fabricated latency displays; latency is derived strictly from server ping/pong round trips.
* **AudioContext Resource Lifecycle**:
  * Replaced ad-hoc audio elements with a shared browser `AudioContext` singleton, preventing resource exhaustion across rapid incident arrivals.
* **GIS Mapping Engine**:
  * Embedded self-contained SVG data URIs for Leaflet marker icons, eliminating external CDN dependencies.
  * Removed hardcoded Google Maps fallback strings. Implemented `window.gm_authFailure` listener that automatically switches to Leaflet tiles if Google authentication fails.
  * Added incremental marker and hazard circle diffing by incident ID to eliminate map flicker on real-time updates.
  * Added visual tactical dispatch vectors connecting assigned units directly to their target coordinates.
* **Client-Side Hash Routing**:
  * Implemented hash routing (`/#/command` for Command Dashboard, `/#/citizen` for Citizen SOS Portal), enabling direct deep-linking on static hosts.
* **Accessibility (WCAG AA) & Data Selection**:
  * Removed global `select-none` on incident tables, transcripts, hashes, and coordinates, allowing operators to copy critical data.
  * Fixed low-contrast color pairs to meet WCAG AA standards ($>4.5:1$ ratio).
  * Added descriptive `aria-label`s and keyboard navigation focus states across all action buttons and modals.
* **Measured Performance**:
  * Benchmarked local pipeline latencies using `scripts/benchmark.py` and displayed measured latencies in `PitchDeckModal`.

## 3. What Could Not Be Fixed Automatically (Manual Owner Actions)

The following items cannot be performed by an automated AI agent and must be completed manually by the repository owner / GCP project administrator:

1. **Google Maps API Key Revocation & Rotation**:
   * **Why**: The leaked API key (`AIzaSyAO...`) is in public git history. Even though removed from source code, it remains active on Google Cloud Console until rotated or deleted.
   * **Required Owner Action**: Navigate to [Google Cloud Console Credentials](https://console.cloud.google.com/apis/credentials), locate the compromised key, and click **Delete**.
2. **API Key Scope and HTTP Referrer Restrictions**:
   * **Why**: Creating and configuring new Google Cloud API credentials requires GCP project owner permissions.
   * **Required Owner Action**: Create a new API key. Under **Application restrictions**, select **Websites (HTTP referrers)** and restrict to authorized domains (e.g., `http://localhost:5173/*`, `http://localhost:8000/*`, and production domain). Under **API restrictions**, select **Restrict key** and check ONLY **Maps JavaScript API**.
3. **Billing Quota & Budget Alerts**:
   * **Why**: Cloud billing management requires access to the Google Cloud Billing Account.
   * **Required Owner Action**: Set a daily quota cap on the Maps JavaScript API and configure a billing budget alert (e.g., $10/month) in Google Cloud Billing to prevent unexpected charges.
4. **Git History Purge**:
   * **Why**: Ground rules explicitly prohibit the agent from force-pushing or rewriting remote git history.
   * **Required Owner Action**: If the repository is public and history rewriting is desired, execute:
     ```bash
     git filter-repo --replace-text <(echo "<LEAKED_KEY_HERE>==>REMOVED_KEY") --force
     git push origin main --force
     ```
     *(Detailed instructions are documented in `SECURITY_TODO.md`)*.
